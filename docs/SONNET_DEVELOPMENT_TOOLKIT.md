# SONNET DEVELOPMENT TOOLKIT — инструменты и пайплайн для моделей уровня Sonnet

Цель: модель уровня Claude Sonnet должна выдавать код и графику проекта без выдуманных API, без поломки соседних зон и без «работает, наверное». Достигается не длинными промптами, а тремя вещами: узким набором библиотек, внешней памятью (документация и спецификации) и автоматическими воротами после каждого шага.

Состояние инструментов — на 2026-11-15. Перечень плагинов, хуков и MCP с разрешениями — `CLAUDE_TOOLS.md` (этот документ его не дублирует, а говорит, **как** ими пользоваться).

---

## 0. Десять правил работы Sonnet в этом проекте

1. **Один шаг — одна цель.** Не больше 3 файлов исходников и ~200 строк диффа. Задача крупнее — остановись и попроси architect её разбить.
2. **Сначала читай, потом пиши.** Файл, который меняешь, прочитан целиком в этом же сеансе. Его тест — тоже. Номера строк из документов — подсказка, а не истина.
3. **API — из документации, не из памяти.** Для `three`, `@react-three/fiber`, `@react-three/drei`, `tone`, `zustand`, `framer-motion`, Playwright, Vite: Context7 (`resolve-library-id` → `query-docs`) с версией из `package.json`. Нет в документации — не используй.
4. **Числа — из спецификаций.** Тайминги, формулы, бюджеты берутся из пяти документов корня. Не округляй, не «улучшай», не подбирай на глаз.
5. **Сначала тест, потом код** — для логики (`src/simulation`, `src/data`, чистые функции кинематики, геометрии, звука). Тест должен упасть до правки.
6. **Своя зона.** Список файлов — в описании агента. Чужой файл не трогается; нужное изменение формулируется как запрос architect.
7. **Без заглушек.** Нет `TODO`, пустых обработчиков, «временных» констант, закомментированного кода. Не можешь доделать — не начинай этот кусок и скажи об этом.
8. **Проверка — команда и её вывод.** «Проверено» значит: команда запущена после последней правки, вывод приложен. Картинка проверяется просмотром PNG, звук — замером; «на слух» пишется только если слушал человек.
9. **Стоп-условия.** Остановись и сообщи, если: тест падает дважды после разных исправлений; нужно изменить тип/стор/конфиг; нужна новая зависимость; документация расходится с кодом; бюджет превышен и причина неясна.
10. **Отчёт по шаблону:** что изменено (файлы) · чем проверено (команды, ключевые строки вывода) · цифры до/после · что не проверено и почему.

## 1. Библиотеки для 3D/2.5D и анимации

### 1.1. Состав

| Пакет | Роль | Почему дружелюбен к кодогенерации |
|---|---|---|
| `three` | Геометрия, материалы, шейдеры, камера | Стабильные базовые классы (`BoxGeometry`, `ExtrudeGeometry`, `InstancedMesh`, `CatmullRomCurve3`, `ShaderMaterial`) — огромный объём примеров, малая изменчивость API ядра |
| `@react-three/fiber` ^9 | Сцена как JSX, цикл кадров, жизненный цикл GPU-ресурсов | Декларативно: дерево компонентов вместо императивного `scene.add`; автоматический `dispose`; один понятный хук кадра `useFrame`; режим `frameloop` решает фоновую остановку одной пропсой |
| `@react-three/drei` ^10 | Готовые помощники | Используется выборочно — только то, что перечислено в `TRANSITION_TO_3D_AND_KINEMATICS.md` §1.3 |
| `@types/three` (dev) | Типы | TypeScript ловит неверные аргументы конструкторов до запуска |
| `framer-motion` (уже есть) | Анимация **UI** (панели, карточки) | Остаётся только для интерфейса |

### 1.2. Про `gsap` и `framer-motion-3d`

- **`framer-motion-3d` использовать нельзя**: пакет снят с поддержки в npm и требует `@react-three/fiber 8.2.2` — он несовместим с fiber 9 и React 19 проекта.
- **`gsap` (3.15.1) технически совместим, но в этот проект не добавляется.** Причины: (1) у gsap собственный тикер — ещё одна шкала времени, которую нужно отдельно останавливать в скрытой вкладке и синхронизировать с часами симуляции; (2) все анимации проекта либо привязаны к прогрессу события (`getEventProgress()`), либо являются пружинами/сглаживанием — для них уже есть `damp`, `lerp`, `smooth` в `src/utils/math.ts` и `stepSpring`; (3) пролёт камеры — параметрическая кривая `CatmullRomCurve3` с одной функцией плавности, таймлайны не нужны. Если позже появится задача со сложной многодорожечной хореографией, gsap рассматривается отдельным решением architect с карточкой security-reviewer.

Итог: связка «`three` + `@react-three/fiber` + `@react-three/drei` + собственные `damp`/`spring`» даёт декларативную генерацию 3D-сцены кодом и одну шкалу времени.

### 1.3. Шаблоны, которые Sonnet копирует (а не изобретает)

Кадр без аллокаций:
```tsx
const _m = new THREE.Matrix4(); const _p = new THREE.Vector3(); const _q = new THREE.Quaternion(); const _s = new THREE.Vector3(1, 1, 1)
function Trains({ curve, count }: { curve: THREE.CatmullRomCurve3; count: number }) {
  const ref = useRef<THREE.InstancedMesh>(null)
  useFrame(() => {
    const mesh = ref.current
    if (!mesh) return
    for (let i = 0; i < count; i++) {
      curve.getPointAt(phaseOf(i), _p)                 // второй аргумент — целевой вектор, без new
      _m.compose(_p, _q, _s)
      mesh.setMatrixAt(i, _m)
    }
    mesh.instanceMatrix.needsUpdate = true
  })
  return <instancedMesh ref={ref} args={[undefined, undefined, count]}><boxGeometry args={[6, 2, 2]} /><meshLambertMaterial /></instancedMesh>
}
```
Ресурс один раз: `const geometry = useMemo(() => buildGeometry(data), [data])` + `useEffect(() => () => geometry.dispose(), [geometry])` для геометрий, созданных вручную (созданные через JSX освобождает R3F).
Uniform без ререндера: `material.uniforms.uNight.value = v` в `useFrame` или в подписке `useWorldStore.subscribe`, не через пропсы React.
Чтение стора в кадре: `useWorldStore.getState()` (не хук).

Сигнатуры в шаблонах сверяются через Context7 перед первым использованием.

Они нужны только для позиций из `ASSET_REQUESTS.md`, и каждый сгенерированный файл проходит `ASSET_PIPELINE.md` (исходник в `assets/source`, лицензия, запись в `ASSET_MANIFEST.md`, оптимизация, вердикт арт-директора).

### 2.2. Playwright MCP для визуальной проверки 3D-сцен

Зачем отдельно от `npm run e2e:visual`: эталонные тесты отвечают «изменилось ли», а агенту нужно **посмотреть**, что получилось, и исследовать интерактивно.

Порядок для qa-engineer / graphics-engineer:
1. Запустить `npm run dev` (порт 5173).
2. `browser_navigate` → `http://localhost:5173/?time=x60&perf`.
3. `browser_click` по `[data-testid=enter-button]`; дождаться сцены (`browser_wait_for`).
4. Открыть карту: `browser_press_key` `m`.
5. `browser_take_screenshot` → открыть файл инструментом Read и описать, что видно (река, кольца, кварталы, ориентиры, герой).
6. `browser_evaluate` — снять объективные признаки:
   ```js
   () => { const c = document.querySelector('canvas[data-engine]'); const gl = c?.getContext('webgl2') ?? c?.getContext('webgl');
           const px = new Uint8Array(4 * 64); gl?.readPixels(c.width / 2 - 4, c.height / 2 - 4, 8, 8, gl.RGBA, gl.UNSIGNED_BYTE, px);
           return { w: c?.width, h: c?.height, distinct: new Set(px).size, info: window.__gl?.info } }
   ```
   (`window.__gl` — отладочный хук с `renderer.info`, который graphics-engineer добавляет под `?perf`; чтение пикселей требует `preserveDrawingBuffer` только в режиме `?perf`.) Canvas одноцветный (`distinct ≤ 2`) — сцена не отрисовалась.
7. `browser_console_messages` — ошибок и предупреждений WebGL (`GL_INVALID_*`, «context lost») быть не должно.
8. Жесты камеры: `browser_drag`, колесо через `browser_evaluate` (диспатч `wheel`) → повторить скриншот.
9. Ночь и погода: `browser_evaluate(() => window.__ml('tverskaya', 'light-rain', 22 * 60))` → скриншот.

Ограничения, о которых агент обязан помнить: headless-браузер без GPU-флагов рисует программно — FPS в нём не показатель (замеры — только `scripts/soak.mjs`, `scripts/gl-stats.mjs`); скрытую вкладку Playwright эмулирует, настоящий фон проверяет `scripts/bg-cpu.mjs`.

### 2.3. Recraft MCP (векторные ассеты) — как подключать, если понадобится

Нужен только если принято решение добавить непроцедурные векторные элементы (иконки пинов, орнаменты станций). Шаги:
1. security-reviewer: карточка — точное имя пакета MCP-сервера и издатель (проверить в npm и в репозитории Recraft; **не устанавливать по имени из памяти модели**), лицензия на результаты генерации, куда отправляются запросы.
2. Пользователь получает ключ API и добавляет сервер командой `claude mcp add` с областью `local` — ключ попадает в `~/.claude.json`, **не** в репозиторий и не в `.mcp.json` проекта.
3. Запись в `CLAUDE_TOOLS.md` (назначение, разрешения, авторизация).
4. Использование — через skill `moscow-asset-pipeline`: сгенерированный SVG очищается (без встроенных растров, без скриптов, без внешних ссылок), приводится к палитре проекта и переносится в `src/scenes/art` как компонент; сырой файл — в `assets/source`.

Запрещено: вставлять SVG из генератора через `dangerouslySetInnerHTML`; оставлять в нём `<script>`, `<foreignObject>`, `href` на внешние адреса.

### 2.4. FLUX и карты глубины

- **FLUX (подключён):** фоновые пластины и текстуры по `ASSET_REQUESTS.md`. Промпт берётся из запроса, результат сохраняется в `assets/source`, сжимается (WebP/AVIF) в `public/`, получает запись в `ASSET_MANIFEST.md`. Расходуются кредиты аккаунта пользователя — перед серией генераций агент называет количество и спрашивает подтверждение.
- **Depth-Anything:** готового MCP-сервера нет. Если понадобится параллакс по карте глубины для сгенерированного фона, это локальный офлайн-шаг: модель запускается на машине пользователя (Python, пакет `transformers`), на вход — файл из `assets/source`, на выход — PNG глубины рядом с ним. Скрипт и зависимости живут вне `src/`; в клиент попадает только готовая карта. Установка Python-пакетов — действие пользователя. Для процедурных SVG-сцен карта глубины не нужна: глубина уже задана пятью Z-плоскостями `CameraRig25D`.

### 3.3. Biome как ворота стиля
`biome.json` — пресет `recommended` + проектные исключения. Для Sonnet это защита от целого класса ошибок без участия человека: неиспользуемые импорты и переменные, пропущенные зависимости хуков (`useExhaustiveDependencies`), присваивания в выражениях, неявный `any`. Команды: `npm run lint` (ошибки блокируют), `npm run lint:fix`, `npm run format`. Предупреждения не игнорируются: либо исправить, либо в отчёте объяснить, почему оно ложное. Подавлять правило комментарием — только с причиной в той же строке.

### 3.5. Цикл одного шага (алгоритм)

```
1. Прочитать: PROGRESS.md → раздел фазы в MASTER_EXECUTION_ROADMAP.md → раздел спецификации → файлы шага.
2. Выписать инварианты шага (из описания агента) и команду проверки.
3. Логика? → написать тест → убедиться, что он падает.
4. Внести правку (≤ 3 файлов).
5. Хук lint сработал → исправить.
6. Запустить «обязательно» из матрицы 3.4.
7. Красное? → одна попытка исправления по причине, а не по симптому. Снова красное → стоп, отчёт о блокировке.
8. Зелёное → «в конце задачи» из матрицы (если шаг последний).
9. Отчёт по шаблону (правило 10) + одна строка в PROGRESS.md.
```

### 3.6. Типичные ошибки моделей уровня Sonnet и чем они ловятся

| Ошибка | Чем ловится |
|---|---|
| Выдуманный метод библиотеки или устаревшая сигнатура | `npm run typecheck`; правило 3 (Context7) |
| `useStore()` без селектора, подписка на быстро меняющееся поле | Grep-инвариант в описании frontend/qa; `bg-cpu.mjs` (коммиты React) |
| Аллокации и `setState` в кадре | чтение тела колбэка по чеклисту graphics-engineer; `soak-heapdiff.mjs` |
| Новый `requestAnimationFrame` / `setInterval` без остановки в фоне | Grep-счётчик у qa-engineer; `bg-cpu.mjs` |
| Литерал 60 вместо `timeScale`, секунды вместо минут | тесты `timing.test.ts`, `simClock.test.ts`; чеклист world-simulation-engineer |
| «Починил» тест, ослабив проверку или обновив эталон | правило qa-engineer: эталоны — только с вердиктом арт-директора; дифф тестов читается при приёмке |
| Узел Web Audio без `stop`/`disconnect`; скачок параметра | `audio-lab` (щелчки), `soak.mjs` (число узлов) |
| Незакрытые ресурсы WebGL | `gl-stats.mjs` (10 циклов открытия карты) |
| Правка чужой зоны «заодно» | приёмка architect: список файлов диффа против зоны агента |
| Отчёт «всё работает» без вывода команд | шаблон отчёта; возврат без рассмотрения |
