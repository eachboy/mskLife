## 2. Фоновый режим «Вкладка для музыки»

### 2.1. Цель
При `document.visibilityState === 'hidden'`: **ноль** кадров (rAF, canvas, WebGL), ноль записей стилей, CPU главного потока ≤ 1.5 % (≤ 0.9 с за 60 с; при `x60` — плюс 0.06 с на событие). При этом симуляция идёт в точном времени, а звук вовремя меняет перегон на остановку и объявляет станцию.

### 2.2. Три класса кода и их правило

| Класс | Что входит | Правило в скрытой вкладке | Механизм |
|---|---|---|---|
| **Визуальный** | `animationClock` (после Фазы 3), `CameraRig25D`, `WeatherRenderer`, `Visualizer`, `EntityLayer`, `LightingController`, `CityMap25D`/`World3DCanvas`, все CSS-анимации | Полная остановка | `onPageVisibility` → отмена rAF/таймеров; CSS — правило `html[data-page-hidden="1"] * { animation-play-state: paused }` (есть, `index.css:373`); R3F — `frameloop='never'` |
| **Симуляция** | `ScenarioEngine`, `WeatherManager`, `WeatherTransitionManager` | Работает; шаг от стенных часов | `SimClock` + воркер-тикер (`REALTIME_TRANSIT_AND_MOVEMENT_SPEC.md` §1) |
| **Звук** | всё в `src/audio` | Работает без изменений | Таймер аудиоконтекста; контекст не приостанавливается |

Проверочный вопрос для любого нового кода: «к какому классу он относится?» Смешивать нельзя: визуальный код не должен вести счёт времени, а симуляция — ждать кадра.

### 2.3. Что остановить (правки)

**B-09, `LightingController.tsx`:**
```ts
apply()
let id = 0
const start = () => { if (!id && !isPageHidden()) id = window.setInterval(apply, 250) }
const stop = () => { if (id) { clearInterval(id); id = 0 } }
const off = onPageVisibility((hidden) => { if (hidden) stop(); else { apply(); start() } })
start()
return () => { off(); stop() }
```
После Фазы 3 интервал заменяется подпиской на `animationClock` с прореживанием до 4 Гц.

**B-05 / B-16, `EntityLayer.tsx`:** позиция сущности — интеграл `x += v * dt` в хабе анимации (в фоне `dt` нет — сущность стоит); удаление — по выходу `x` за кадр, а не по таймеру; спавнер (`loop`) при hidden не перезапускает `setTimeout`, а при возврате стартует заново. До Фазы 3 (пока сущности на CSS) — временная мера: хранить `hiddenAt`, при возврате сдвигать `born` всех живых сущностей на длительность простоя и перевзводить таймеры удаления с остатком.

**B-03, `Hero.tsx`:** анимация героя привязывается к прогрессу события, а не к моменту монтирования. До Фазы 3: Web Animations API — получить анимацию элемента (`el.getAnimations()[0]`) и выставить `currentTime = getEventProgress() * dur` при монтировании и при возврате из фона; `dur = getEventRealMs()`. После Фазы 3 — позиция из хаба.

**B-10:** циклы остановок заменяются фазами события (`REALTIME…SPEC.md` §9). До этого `useRideCycle` обязан останавливать таймеры при hidden и перезапускать цикл при возврате.

**B-06:** подписки на `eventElapsed` убрать. `useHeroGeo` возвращает только то, что меняется со сменой события (`path`, `motion`, `area`); позиция маячка и остаток маршрута пишутся в DOM по ref из хаба анимации: `pos = pointAt(path, getEventProgress())` → `style.transform`; текст «≈ N мин» обновляется раз в секунду через `textContent`. Камера радара следует за героем тем же колбэком.

**Проверка, что остановлено всё** — скрипт `scripts/bg-cpu.mjs` (создаёт BP в Фазе 1). Алгоритм: production-сборка → вход → подмена `requestAnimationFrame`, `CanvasRenderingContext2D.prototype` (`stroke`, `fill`, `drawImage`, `clearRect`), `WebGLRenderingContext.prototype.drawArrays/drawElements`, `CSSStyleDeclaration.prototype.setProperty` счётчиками → открыть вторую вкладку и вывести её на передний план (`page2.bringToFront()`), чтобы первая стала действительно скрытой → 60 с → прочитать счётчики и `Performance.getMetrics` (`TaskDuration`, `ScriptDuration`, `LayoutCount`, `RecalcStyleCount`) через CDP. Ожидание: все счётчики кадров и отрисовок = 0; `TaskDuration` ≤ 0.6 с; `LayoutCount` и `RecalcStyleCount` не растут; `__audio.manager.diagnostics().contextState === 'running'`; номер события симуляции (`eventKey`) вырос.

### 2.4. Как сохранить точный ход симуляции (B-01, B-02)

Полный алгоритм — `REALTIME_TRANSIT_AND_MOVEMENT_SPEC.md` §1. Суть:
1. Шаг — разница `Date.now()`, без ограничения сверху.
2. Игровые минуты шага = `dMs / 60000 * timeScale`.
3. Событий за шаг может закончиться несколько: цикл `while` потребляет их по очереди.
4. Тикер — выделенный воркер 250 мс; запасной путь — `setInterval`. Корректность не зависит от частоты тиков: даже один тик в минуту приводит к верному состоянию, страдает только точность момента звуковой подсказки.

Почему это даёт своевременный звук остановки: при тике 250 мс событие `metro-arriving` применяется не позже чем через 250 мс после своего расчётного момента; `AudioLifecycleManager` получает смену `eventKey` синхронно (подписка на стор) и планирует звук от `ctx.now()`. Модель скорости поезда интегрируется таймером аудиоконтекста, который в фоне не троттлится. Бюджет точности: ≤ 300 мс в видимой вкладке, ≤ 1.2 с в скрытой.

### 2.5. Защита от огромного шага после 3 часов

Два разных правила для двух классов:

| Класс | Правило | Где |
|---|---|---|
| Визуальный | `dt = clampDelta(raw)` ≤ 0.1 с. Физика (пружины, частицы) не «доигрывает» пропущенное время; положения, зависящие от симуляции (герой, поезд, панорама за окном), **восстанавливаются** из `getEventProgress()` и аналитических формул, а не интегрируются | `pageVisibility.ts` (есть), `animationClock.ts` |

## 3. Рендер и память

### 3.1. React: высокочастотное состояние — мимо React

Правило: значение, меняющееся чаще 1 Гц, не хранится в сторе, на который подписаны компоненты.

| Значение | Сейчас | Станет |
|---|---|---|
| Прогресс события | `worldStore.eventElapsed`, 4 Гц | `eventProgress.ts` (`getEventProgress()`), чтение из хаба анимации |
| Игровые минуты | `worldStore.minutes`, 4 Гц (дробные) | запись только при смене целой минуты; дробное значение — `simClock` |
| Поза камеры сцены | модуль `CameraRig25D` (уже вне React) | без изменений |
| Камера карты | CSS-переменные по ref (уже вне React) | без изменений; 3D — `MapCamera` |
| Уровень сигнала визуализатора | canvas + `dataset` (уже вне React) | без изменений |
| Импульс фразы музыки | `audioStore.beat` | оставить, но никто не подписывается на стор целиком (B-08) |

Приём чтения стора без подписки React (zustand, «transient update»):
```ts
useEffect(() => useWorldStore.subscribe((s, prev) => {
  if (s.event !== prev.event) ref.current!.dataset.phase = s.event?.phase ?? ''
}), [])
```
Правки: B-06 (см. §2.3); B-07 — `SettingsPanel` берёт `weatherSource`, `timeMode`, `lowPerf`, `weatherKind` четырьмя селекторами; B-08 — `BottomBar` берёт поля по одному либо `useShallow` для группы громкостей; `MixRow` обернуть в `memo`.

Контроль: `scripts/bg-cpu.mjs` дополнительно считает коммиты React (счётчик в `Profiler` корня при `?perf`). Бюджет в покое: ≤ 2 коммитов в секунду на приложение при 60×, ≤ 1 в минуту при 1:1 в фоне.

**Сущности (B-16)** — целевая схема (`TRANSITION_TO_3D_AND_KINEMATICS.md` §3.6):
```ts
interface Slot {
  active: boolean
  el: SVGGElement | null          // постоянный <g>, создаётся один раз
  kind: 'ped' | 'pair' | 'veh'
  x: number; y: number; v: number; s: number; facing: 1 | -1
  x1: number                      // граница выхода за кадр
  look: number                    // версия «внешности»: меняется → один setState слота

```
- Массив `slots` создаётся один раз на сцену; `EntityBand` рендерит по одному компоненту-слоту на каждый индекс своей полосы (число DOM-поддеревьев постоянно).

- Никаких `setTimeout`, `filter`, копирования массивов.

Приёмка: `node scripts/soak-heapdiff.mjs 2 8` — число объектов типов `SVGGElement`, `SVGPathElement`, `(closure)` между снимками не растёт; `soak.mjs` — DOM-узлы плато ± 2 %.

### 4.1. Освобождение узлов

| Источник узлов | Создание | Освобождение | Статус |
|---|---|---|---|
| Шины, фильтры, компрессор, анализаторы `AudioMixer` | конструктор | `dispose()` (только HMR/тесты) | исправно |

Команда инвентаризации: `Grep "new T\.|createOscillator|createBufferSource|createGain|createBiquadFilter|createConstantSource" src/audio` (без тестов). Каждое совпадение вне `init()`/конструктора — либо пул, либо одноразовый узел с `stop` + `disconnect` по `onended`.

Правило для `AudioBufferSourceNode` и `OscillatorNode`: `start(t)` всегда сопровождается `stop(tEnd)` в том же блоке; `onended = () => { src.disconnect(); gain.disconnect() }`. Узел `GainNode`, оставшийся подключённым к шине после смерти источника, продолжает обрабатываться — это и есть «утечка графа».

### 4.2. Второй AudioContext (B-11)
`AudioMixer` создаёт собственный `T.Context` и делает его текущим, но контекст, который Tone мог создать по умолчанию при первом `getContext()`, остаётся жить. Исправление (сверить сигнатуру через Context7 для tone ^15): `T.setContext(this.context, true)` — второй аргумент закрывает прежний контекст; либо убедиться, что до конструктора микшера никто не вызывает `T.getContext()`/`T.now()`. Проверка: в `diagnostics()` добавить число живых контекстов (подсчёт через обёртку конструктора `AudioContext` при `?audiodebug`) → `soak.mjs` показывает 1.

### 4.3. Щелчки при смене сцен

Правила (все проверяются `signalStats` — детектор щелчков — в `audio-lab`):
1. Любой уровень — рампа ≥ 20 мс; фильтр — `setTargetAtTime` с τ ≥ 0.05 с.
2. Перед новой рампой на параметре, где уже идёт рампа, — `cancelAndHoldAtTime(t)` (а не `cancelScheduledValues`, который возвращает значение скачком) либо только `setTargetAtTime` без отмены (так сделано в `setMapOverviewMode`).
3. Подключение слоя — при усилении 0; отключение — после окончания рампы по `currentTime` + запас 0.1 с (`OutputGate`, уже так).
4. Смена `ambience` локации — кроссфейд слоёв, не пересоздание; длительность = длительности визуального перехода (`transition.ms`), минимум 0.4 с.
5. Одноразовые звуки события с реальной длительностью < 2 с не играются (режим 60×) — иначе на постанционном проезде двери и объявления сольются в треск.
6. События `silent` — без одноразовых звуков (B-13).

Сценарии, которые AE добавляет в лабораторию: «постанционный проезд 5 станций при 15×», «перемотка 3 ч», «смена пространства улица → вестибюль → эскалатор → платформа → вагон за 20 с», «открытие/закрытие карты 10 раз подряд», «смена timeMode посреди перегона».
