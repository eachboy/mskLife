# 5. ДОПОЛНИТЕЛЬНЫЕ NODE.JS ИНСТРУМЕНТЫ

Проанализируй package.json и установи только действительно необходимые зависимости.

Рекомендуемые кандидаты:

## Testing

- @playwright/test
- vitest
- @vitest/coverage-v8
- @testing-library/react
- @testing-library/user-event
- @testing-library/jest-dom
- @axe-core/playwright

Задача — полноценное функциональное, визуальное и accessibility-тестирование.

## Graphics

- pixi.js
- @pixi/react — если оправдано используемой архитектурой.
- sharp
- zod

PixiJS особенно интересен для MOSCOW LIFE, потому что позволяет построить производительный 2D/2.5D renderer с:
- Спрайтами.
- Частицами.
- Слоями.
- Текстурами.
- Масками.
- Фильтрами.
- Анимацией большого количества объектов.

Не подключай одновременно PixiJS и Three.js без необходимости.

Если существующий renderer хорошо работает, не меняй его только ради новой библиотеки.

## Audio

- tone

При необходимости дополнительно используй специализированные инструменты обработки аудиосигнала.

Не подключай дополнительные аудиобиблиотеки, которые создают второй независимый AudioContext или конфликтуют с существующим Audio Engine.

## Performance

- web-vitals
- lighthouse

Подключи сбор метрик производительности и создай отчет.

## PWA

- vite-plugin-pwa

Рассмотри возможность создания устанавливаемого PWA.

PWA нужен для:
- Установки на устройство.
- Кэширования ассетов.
- Быстрого повторного запуска.
- Более законченного пользовательского опыта.

Не используй Service Worker как средство искусственного поддержания непрерывного аудиовоспроизведения при замороженной странице.

Проверяй:
- Наличие ошибок.

- Тесты.
- Изменения в архитектуре.
- Незавершенные задачи.

### Защита проекта

Добавь правила, предотвращающие:
- Случайное удаление важных файлов.
- Публикацию секретов.
- Перезапись ассетов без сохранения исходников.
- Установку неизвестных зависимостей без проверки.
- Неконтролируемое изменение конфигурации.

Hooks должны быть быстрыми и не должны создавать бесконечный цикл автоматических запусков.

# 9. НАСТРОИТЬ МУЛЬТИАГЕНТНЫЙ WORKFLOW

Главный агент — Project Architect.

Он распределяет задачи между специалистами.

Пример работы:

Пользователь просит улучшить систему дождя.

Project Architect:
1. Изучает текущую архитектуру.
2. Ставит задачу World Designer.
3. Передает аудиокомпонент Audio Engineer.
4. Передает визуальную реализацию Graphics Engineer.
5. Передает интеграцию Frontend Developer.

После реализации:

6. QA Engineer проводит тестирование.
7. Visual Art Director оценивает качество.
8. User Simulator оценивает результат с пользовательской позиции.
9. Project Architect принимает замечания.
10. Исполнители исправляют ошибки.
11. QA проводит повторную проверку.

Используй параллельное выполнение только для независимых задач.

Избегай одновременного редактирования одинаковых файлов несколькими агентами.
