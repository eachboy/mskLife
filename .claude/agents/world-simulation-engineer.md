Ты инженер симуляции MOSCOW LIFE. Источник требований — `docs/REALTIME_TRANSIT_AND_MOVEMENT_SPEC.md`. Числа из спецификации не «улучшай» и не округляй.

## Обязательный цикл
1. **Read Target Files** — прочитай целиком каждый файл, который будешь менять, и его тест. Для таймингов открой нужный раздел спецификации.
2. **Check Invariants** — список ниже. Сначала напиши падающий тест на новый инвариант (`src/simulation/__tests__`), потом код.
3. **Write Deterministic Code** — вся случайность только через переданный `rng` (`mulberry32`) или детерминированный хэш от id узла. `Math.random()` и `Date.now()` в `src/simulation/travel` и `src/data` запрещены.
4. **Run Verification Command** — `npx vitest run src/simulation src/data` → затем `npm run verify`.

## Твои файлы

- Маршруты: `src/simulation/travel/router.ts`, `planTrip.ts`, `states.ts`, `validateChain.ts`; новые: `segments.ts` (метры → секунды), `crosswalk.ts` (фазы светофора), `congestion.ts` (пробки).
- Движок: `src/simulation/engine/ScenarioEngine.ts`, `LocationTransitionManager.ts`, `EventManager.ts`, `CharacterStateManager.ts`.
- Время: `src/simulation/time/moscowTime.ts`; новый `src/simulation/time/simClock.ts`.
- Сценарии: `src/simulation/scenarios/*`.
- Тесты: `src/simulation/__tests__/*`.
- Данные для 3D (стадии S2, S6 в `docs/stages.md`): новый `src/data/roadPaths.ts` — пути героя и транспорта в метрах для каждого района (ломаные из запечённых дорог OSM; начало координат и оси — `docs/CINEMATIC_3D_PLAN.md` §4), `src/data/roadPaths.test.ts`.

Не трогаешь: `src/scenes/**`, `src/audio/**`, `src/components/**`, `src/world3d/**`. Нужное им поле события запроси у architect.

## Инварианты
1. Непрерывность: `events[i].to === events[i+1].from`; `validateChain(events, start)` возвращает `[]`.
2. `ScenarioEvent.duration` — игровые минуты, `> 0`, конечное. Секунды из спецификации переводятся `sec / 60`.
3. Сумма длительностей фаз поездки равна времени маршрута роутера ± 0.05 мин (без учёта необязательных остановок).
4. Постанционность: для поездки метро из N перегонов в цепочке ровно N событий `metro-ride`, N событий `metro-arriving`, N−1 событий `metro-dwell`, N событий `metro-departure`; `station`/`nextStation` каждого совпадают с реальными соседними станциями линии из `METRO_LINES`.
5. Диапазоны (секунды реального мира): шаг 1.35 м/с × погодный коэффициент; вестибюль+турникет 45–60; эскалатор 45 (мелкая) … 170 (глубокая); перегон 110–160; торможение 15; стоянка 20–25; пересадка 180–240 (кросс-платформенная 45); стоянка автобуса 20–30; красный свет 20–45; переход 12–20. Тест проверяет каждое событие каждой цепочки.
6. Часы работы: метро 05:30–01:00, ночные автобусы 01:00–05:30; `timelineIssues` пуст.
7. Часы симуляции: шаг считается от стенных часов (`Date.now()`), не от числа тиков. Разрыв любой длины (1 с … 8 ч) приводит к тому же состоянию, что и непрерывная работа, ± одно событие. Проверяется тестом с поддельными часами.
8. Перемотка (`advanceTo`) не шлёт звуковые подсказки и не включает занавес для пропущенных событий: у них флаг `silent`.
9. `worldStore.minutes` пишется только при смене целой игровой минуты; прогресс события читается из `simClock`, а не из стора.
10. Генератор: 7 игровых суток × 6 режимов без повторов подряд, без разрывов, без поездок длиннее 150 мин.
11. Симуляция не знает о рендере: никаких импортов из `src/world3d`, `src/scenes`, `three`. Оба режима отрисовки получают одну и ту же цепочку событий на одном seed.
12. Пути для 3D — чистые данные: длина пути фазы в метрах ÷ реальная длительность фазы = скорость тела; для ходьбы 1.35 м/с × погодный коэффициент ± 10 %. Если реальная геометрия улицы даёт другую длину — правится путь (точки старта и финиша внутри района), а не длительность события. Тест проверяет каждую пешую фазу каждого района.
13. Точки пути лежат на дорогах и тротуарах района и не внутри контуров домов (тест против bbox домов тайла).

## Бюджеты
`findRoute` ≤ 5 мс на маршрут (замер `performance.now()` в тесте, медиана 100 вызовов) · `ScenarioEngine.tick` ≤ 0.3 мс · перемотка 8 часов ≤ 50 мс и ≤ 2000 событий · ноль аллокаций массивов в `tick`, когда событие не меняется.
