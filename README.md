# MOSCOW LIFE
Бесконечная LoFi-симуляция жизни Москвы: уютная иллюстрированная сцена, процедурная музыка, погода, прохожие и герой, который живёт по расписанию дня.

## Запуск
```
npm install
npm run dev        # http://localhost:5173
npm run build && npm run preview
npm test           # Vitest
npm run e2e        # Playwright (нужен: npx playwright install chromium)
```
Нажмите «ENTER MOSCOW» (звук включается после клика). Space — пауза, F — полный экран, Esc — закрыть панель.

## Возможности
- 20 локаций (данные), 7 типов сцен, плавная смена дня/ночи и сезонов.
- 10 погодных состояний; симуляция или реальная погода Москвы (Open-Meteo) с откатом на симуляцию при ошибке.
- Процедурная LoFi-музыка 65–90 BPM, джазовые аккорды, свинг, винил; три независимые громкости (музыка/город/погода).
- 6 сценариев: свободный, рабочий день, дождливый, зимний, ночной, случайный. Переходы только цепочкой событий (пешком/автобус/метро).
- Режим низкой нагрузки в настройках.

Архитектура и правила: `CLAUDE.md`, ассеты: `docs/ASSET_MANIFEST.md`, журнал: `PROGRESS.md`.

## Фоновое воспроизведение и ограничения
Звук живёт в `AudioLifecycleManager` (синглтон вне React): скрытие вкладки, сворачивание окна, потеря фокуса и размонтирование UI **не** вызывают `suspend()`/`close()` и не останавливают Transport. Планировщик музыки и обновления города/погоды работают на таймере аудиоконтекста (Tone, Worker), а не на `setInterval`/`requestAnimationFrame` главного потока, поэтому троттлинг таймеров фоновой вкладки на музыку не влияет. При возврате (`visibilitychange`, `pageshow`, `resume`, `focus`, первый жест) менеджер проверяет состояние контекста и Transport и при необходимости возобновляет их без второго экземпляра. Визуальная часть при скрытии отдыхает: браузер останавливает `requestAnimationFrame`, спавн прохожих пауза.

Что проверено автоматически (`npx playwright test -c scripts/soak.playwright.config.mjs`, `e2e/lifecycle.spec.ts`): вторая вкладка поверх и свёрнутое окно в Chromium/Edge без эмуляции Playwright, заморозка `Page.setWebLifecycleState frozen → active`, повторный ENTER/старт, повторный монтаж панелей. Soak 30+ минут — `node scripts/soak.mjs` (отчёт `D:/dev-cache/tmp/soak/SOAK_REPORT.md`).

Чего обычная веб-страница гарантировать **не может**:
- **Сон/гибернация ОС, закрытая крышка ноутбука.** Процессор и аудиоустройство остановлены — звука нет ни у одной программы. После пробуждения контекст обычно продолжает работу сам или по первому клику (`interrupted`/`suspended` → подсказка в UI); музыкальная позиция не «догоняет» пропущенное.
- **Выключенный экран** — звук продолжается, только если ОС и браузер продолжают аудиопроцесс (на ПК обычно да; на мобильных — зависит от энергосбережения).
- **Заморозка страницы браузером.** Chrome может заморозить фоновую вкладку (Page Lifecycle `freeze`), Memory Saver / «спящие вкладки» Edge — выгрузить её (`document.wasDiscarded`). Вкладка, которая воспроизводит звук, обычно от этого защищена, но это политика браузера, а не гарантия; выгруженная вкладка при возврате перезагружается с нуля (нужен новый клик ENTER).
- **Мобильные браузеры.** iOS Safari и Android Chrome приостанавливают Web Audio при блокировке экрана/уходе в фон по своим правилам; `AudioContext` может перейти в `interrupted` (звонок, Bluetooth-гарнитура). Восстанавливаем по следующему жесту.
- **Закрытый браузер или убитый процесс вкладки** — звук прекращается; сохраняются только настройки громкости/визуализатора (localStorage), симуляция начинается заново.
- **Service Worker не держит Web Audio**: он не имеет доступа к AudioContext и не предотвращает заморозку страницы. Скрытые `<video>`/тихие осцилляторы как «хак удержания» не используем — это против политик браузеров и расходует батарею.

Для настоящего фонового плеера нужен другой класс приложения: PWA с Media Session (`navigator.mediaSession` — метаданные и кнопки ОС; на части платформ продлевает жизнь вкладки, но не гарантирует её) или desktop-обёртка (Electron/Tauri: `backgroundThrottling: false`, `powerSaveBlocker` — запрет сна по желанию пользователя).
